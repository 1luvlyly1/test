Cheatsheet LangChain · LangGraph · Guardrails

Cập nhật 01/10/2026 · LangChain/LangGraph 1.x

1. Tổng quan: ai làm gì

LangChain dựng app/agent nhanh; LangGraph điều phối luồng có trạng thái; Guardrails chặn input/output không an toàn. Từ bản 1.0 (10/2025), agent của LangChain chạy trên nền LangGraph.

Thành phần Vai trò Từ khóa phải nhớ
langchain-core Abstraction chung: Runnable, messages, prompts, tools Runnable, invoke, toán tử pipe
langchain (1.x) API cấp cao để dựng agent create_agent, init_chat_model, middleware
langchain-classic Code cũ (0.x) chuyển sang đây LLMChain, RetrievalQA, memory cũ
langchain-openai, -anthropic… Package tích hợp theo nhà cung cấp ChatOpenAI, ChatAnthropic
langgraph Runtime đồ thị có state, bền vững StateGraph, checkpointer, interrupt
LangSmith Tracing, đánh giá, monitor LANGSMITH_TRACING=true
Guardrails Kiểm soát an toàn input/output/tool PII, prompt injection, HITL
  • Dùng LangChain khi cần agent chuẩn (vòng lặp model ↔ tool) nhanh, ít code.
  • Dùng LangGraph khi cần kiểm soát luồng: rẽ nhánh, vòng lặp tùy biến, nhiều agent, tạm dừng chờ người duyệt.
  • create_react_agent (langgraph.prebuilt) bị thay bằng langchain.agents.create_agent ở bản 1.0.

2. LangChain core

Mọi thành phần (model, prompt, parser, retriever, chain) đều là Runnable, nên ghép được bằng toán tử | (LCEL).

Model & messages

from langchain.chat_models import init_chat_model
model = init_chat_model("openai:gpt-4o", temperature=0)  # "provider:model"

from langchain.messages import SystemMessage, HumanMessage, AIMessage, ToolMessage
model.invoke([SystemMessage("Bạn là trợ lý"), HumanMessage("Xin chào")])
# hoặc dạng dict: [{"role": "user", "content": "Xin chào"}]
Message Vai trò (role) Ghi chú
SystemMessage system Chỉ dẫn hành vi cho model
HumanMessage user Input người dùng
AIMessage assistant Có .content, .tool_calls, .usage_metadata
ToolMessage tool Kết quả tool, bắt buộc có tool_call_id

Runnable interface (LCEL)

Phương thức Dùng khi
invoke(x) / ainvoke 1 input → 1 output
batch([x1, x2]) / abatch Nhiều input song song
stream(x) / astream Nhận output từng chunk
with_retry(), with_fallbacks([...]) Thử lại / model dự phòng
with_config({"tags":…}) Gắn tag, callbacks, run_name 
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnablePassthrough, RunnableParallel, RunnableLambda

prompt = ChatPromptTemplate.from_messages([
    ("system", "Trả lời ngắn gọn bằng {lang}"),
    MessagesPlaceholder("history"),   # chèn list message
    ("human", "{question}"),
])
chain = prompt | model | StrOutputParser()
chain.invoke({"lang": "tiếng Việt", "history": [], "question": "LCEL là gì?"})
  • RunnablePassthrough(): chuyển input đi nguyên vẹn; .assign(k=...) thêm khóa mới.
  • RunnableParallel({"a": r1, "b": r2}): chạy song song, trả dict. Một dict literal trong chain tự thành RunnableParallel.
  • RunnableLambda(f): bọc hàm Python thành Runnable.
  • Output parser: StrOutputParser, JsonOutputParser, PydanticOutputParser (có get_format_instructions()).

Structured output & tools

from pydantic import BaseModel, Field
class Movie(BaseModel):
    title: str = Field(description="Tên phim")
    year: int
model.with_structured_output(Movie).invoke("Phim Inception?")  # -> Movie(...)

from langchain.tools import tool
@tool
def get_weather(city: str) -> str:
    """Lấy thời tiết của một thành phố."""   # docstring = mô tả cho model
    return f"{city}: 30°C"

msg = model.bind_tools([get_weather]).invoke("Thời tiết Hà Nội?")
msg.tool_calls  # [{'name': 'get_weather', 'args': {'city': 'Hà Nội'}, 'id': '...'}]
  • bind_tools chỉ để model đề xuất gọi tool; model không tự chạy tool. Code (hoặc agent/ToolNode) phải chạy và trả ToolMessage.
  • Tên hàm, docstring và type hint quyết định schema tool mà model nhìn thấy.
  • with_structured_output dùng tool calling hoặc JSON mode của provider để ép output theo schema.

3. LangChain agents (create_agent + middleware)

create_agent dựng sẵn vòng lặp ReAct: model → (gọi tool → model)* → trả lời khi không còn tool call. Nó trả về một LangGraph đã compile.

from langchain.agents import create_agent
from langgraph.checkpoint.memory import InMemorySaver

agent = create_agent(
    model="openai:gpt-4o",          # chuỗi hoặc object chat model
    tools=[get_weather],
    system_prompt="Bạn là trợ lý thời tiết.",
    middleware=[...],                # guardrail, summarize, HITL...
    response_format=Movie,           # structured output (tùy chọn)
    checkpointer=InMemorySaver(),    # bộ nhớ ngắn hạn
)
config = {"configurable": {"thread_id": "user-1"}}
res = agent.invoke({"messages": [{"role": "user", "content": "Hà Nội?"}]}, config)
res["messages"][-1].content       # câu trả lời cuối
res["structured_response"]        # nếu có response_format

Middleware hooks (thứ tự chạy)

Hook Chạy khi Dùng cho
before_agent 1 lần, đầu mỗi invoke Kiểm tra input, auth, chặn sớm
before_model Trước mỗi lần gọi model Cắt/tóm tắt history, đổi state
wrap_model_call Bao quanh lời gọi model Retry, fallback, đổi model/tools động
wrap_tool_call Bao quanh lời gọi tool Retry tool, kiểm tra args, xử lý lỗi
after_model Sau mỗi lần gọi model Kiểm tra output, HITL
after_agent 1 lần, cuối invoke Kiểm tra câu trả lời cuối
  • Viết bằng class AgentMiddleware hoặc decorator @before_agent, @after_model, @wrap_model_call, @dynamic_prompt…
  • Hook trả None = không đổi gì; trả dict = cập nhật state.
  • Muốn dừng sớm: khai báo can_jump_to=["end"] rồi trả {"jump_to": "end"}. Đích hợp lệ: "model", "tools", "end".
  • Nhiều middleware: hook before_* chạy theo thứ tự list, after_* chạy ngược lại, wrap_* lồng nhau (cái đầu bọc ngoài cùng).

Middleware có sẵn hay hỏi

Middleware Tác dụng
SummarizationMiddleware Tóm tắt history khi gần chạm giới hạn token
HumanInTheLoopMiddleware Tạm dừng chờ duyệt trước khi chạy tool nhạy cảm
PIIMiddleware Phát hiện và xử lý PII (redact/mask/hash/block)
ModelCallLimitMiddleware / ToolCallLimitMiddleware Giới hạn số lần gọi, chống vòng lặp vô hạn
ModelFallbackMiddleware Chuyển sang model dự phòng khi lỗi
ToolRetryMiddleware Thử lại tool lỗi
LLMToolSelectorMiddleware Dùng LLM chọn bớt tool liên quan
TodoListMiddleware Cho agent tool lập kế hoạch dạng todo

Memory, context, streaming

  • Bộ nhớ ngắn hạn (trong 1 hội thoại) = checkpointer + thread_id. Bộ nhớ dài hạn (xuyên thread) = store.
  • State tùy biến: state_schema kế thừa AgentState. Dữ liệu tĩnh mỗi lần chạy (user_id, DB conn): context_schema + agent.invoke(..., context=...), đọc qua runtime.context.
  • Structured output: ToolStrategy(Schema) (qua tool calling, mọi model hỗ trợ tool) hoặc ProviderStrategy(Schema) (structured output gốc của provider).
  • Streaming: agent.stream(input, stream_mode=...) với "updates" (thay đổi sau mỗi bước), "messages" (token LLM), "values" (toàn bộ state), "custom" (dữ liệu tự phát).

4. RAG trong LangChain

RAG = lấy đoạn tài liệu liên quan rồi đưa vào prompt, để model trả lời dựa trên dữ liệu thật thay vì trí nhớ.

  1. Indexing (offline): Load → Split → Embed → Store.
  2. Retrieval & generation (online): Query → Retrieve top-k → Nhét vào prompt → LLM trả lời.
from langchain_community.document_loaders import WebBaseLoader   # PyPDFLoader, CSVLoader...
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_openai import OpenAIEmbeddings
from langchain_core.vectorstores import InMemoryVectorStore       # FAISS, Chroma, PGVector...

docs = WebBaseLoader("https://...").load()                  # list[Document]
splits = RecursiveCharacterTextSplitter(
    chunk_size=1000, chunk_overlap=200).split_documents(docs)
vs = InMemoryVectorStore.from_documents(splits, OpenAIEmbeddings())
retriever = vs.as_retriever(search_type="mmr", search_kwargs={"k": 4})

rag_chain = (
    {"context": retriever, "question": RunnablePassthrough()}
    | prompt | model | StrOutputParser()
)
Khái niệm Cần nhớ
Document Có page_content và metadata
chunk_size / chunk_overlap Kích thước mỗi đoạn / phần chồng lấn giữ ngữ cảnh ở ranh giới
RecursiveCharacterTextSplitter Tách theo thứ tự \n\n → \n → khoảng trắng; splitter mặc định nên dùng
search_type="similarity" Lấy k đoạn gần nhất (cosine)
search_type="mmr" Max Marginal Relevance: vừa liên quan vừa đa dạng, giảm trùng lặp
similarity_score_threshold Chỉ lấy đoạn vượt ngưỡng điểm
MultiQueryRetriever LLM sinh nhiều biến thể câu hỏi để tăng recall
ParentDocumentRetriever Tìm bằng chunk nhỏ, trả về đoạn cha lớn hơn
EnsembleRetriever Kết hợp BM25 (từ khóa) + vector (ngữ nghĩa) = hybrid search
  • Agentic RAG: bọc retriever thành tool (@tool hoặc create_retriever_tool), để agent tự quyết khi nào cần tra cứu.
  • Rủi ro bảo mật của RAG: tài liệu truy xuất có thể chứa prompt injection gián tiếp → coi nội dung retrieve là dữ liệu, không phải chỉ dẫn.

5. LangGraph: State, Node, Edge

Một graph LangGraph = State (dữ liệu chung) + Node (hàm xử lý) + Edge (luồng đi). Node nhận state, trả về phần state cần cập nhật; reducer quyết định cách gộp.

from typing import Annotated, TypedDict
import operator
from langgraph.graph import StateGraph, START, END, MessagesState
from langgraph.graph.message import add_messages
from langgraph.prebuilt import ToolNode, tools_condition

class State(TypedDict):
    messages: Annotated[list, add_messages]  # reducer: nối thêm, gộp theo id
    steps: Annotated[int, operator.add]      # reducer: cộng dồn
    topic: str                               # không reducer: ghi đè

llm_with_tools = model.bind_tools([get_weather])
def call_model(state: State):
    return {"messages": [llm_with_tools.invoke(state["messages"])], "steps": 1}

builder = StateGraph(State)
builder.add_node("agent", call_model)
builder.add_node("tools", ToolNode([get_weather]))
builder.add_edge(START, "agent")
builder.add_conditional_edges("agent", tools_condition)  # có tool_calls -> "tools", không -> END
builder.add_edge("tools", "agent")                       # vòng lặp ReAct
graph = builder.compile(checkpointer=InMemorySaver())

Model trả tool_calls thì đi sang ToolNode rồi quay lại; không còn tool_calls thì tới END. Đây cũng chính là graph mà create_agent dựng sẵn.

Khái niệm Ý nghĩa
StateGraph(State) Builder; phải .compile() mới chạy được
START, END Node ảo bắt đầu / kết thúc
add_edge(a, b) Luôn đi a → b
add_conditional_edges(a, fn, path_map) fn(state) trả tên node kế tiếp (hoặc list tên)
Reducer Mặc định ghi đè; add_messages cho chat; operator.add cho list/số
MessagesState State có sẵn khóa messages với add_messages
ToolNode Node chạy các tool_calls của AIMessage cuối, trả ToolMessage
tools_condition Router: có tool call → "tools", không → END
recursion_limit Giới hạn số super-step (mặc định 25) → GraphRecursionError

Command và Send

from langgraph.types import Command, Send
from typing import Literal

def router(state) -> Command[Literal["billing", "support"]]:
    return Command(update={"topic": "bill"}, goto="billing")  # cập nhật + điều hướng trong 1 bước

def fan_out(state):   # map-reduce: tạo số nhánh động lúc chạy
    return [Send("summarize", {"doc": d}) for d in state["docs"]]
builder.add_conditional_edges("split", fan_out, ["summarize"])
  • Command(goto=..., update=...): node vừa đổi state vừa chọn node kế tiếp, không cần conditional edge. Command(graph=Command.PARENT) để nhảy ra graph cha (handoff giữa agent).
  • Send(node, arg): gửi state riêng cho mỗi nhánh song song; số nhánh chỉ biết lúc chạy.
  • Node chạy song song trong cùng super-step; mọi update gộp qua reducer, nên khóa bị nhiều nhánh ghi cùng lúc phải có reducer (nếu không → InvalidUpdateError).
  • Subgraph: graph đã compile có thể làm node trong graph khác; chung khóa state thì truyền thẳng.

6. LangGraph: persistence, human-in-the-loop, multi-agent

Checkpointer lưu snapshot state sau mỗi super-step theo thread_id; đây là nền tảng cho memory, interrupt, time travel và chịu lỗi.

Checkpointer và Store

Checkpointer Store
Phạm vi 1 thread (1 hội thoại) Xuyên thread, xuyên user
Dùng cho Memory ngắn hạn, HITL, resume, time travel Memory dài hạn (sở thích user, fact)
Class InMemorySaver, SqliteSaver, PostgresSaver InMemoryStore, PostgresStore
Khai báo compile(checkpointer=...) compile(store=...); truy cập store.put/get/search(namespace, key)
Khóa config["configurable"]["thread_id"] namespace tuple, ví dụ ("memories", user_id)
  • InMemorySaver chỉ để dev/test (mất khi tắt process); production dùng Postgres/SQLite.
  • graph.get_state(config) → snapshot hiện tại (.values, .next); get_state_history(config) → các checkpoint cũ; update_state(config, values) → sửa state thủ công.
  • Time travel: lấy checkpoint_id cũ, gọi graph.invoke(None, {"configurable": {"thread_id": ..., "checkpoint_id": ...}}) để replay hoặc rẽ nhánh (fork).

Human-in-the-loop với interrupt

from langgraph.types import interrupt, Command

def approve(state):
    decision = interrupt({"question": "Duyệt gửi email?", "draft": state["draft"]})
    return {"approved": decision == "yes"}

graph = builder.compile(checkpointer=InMemorySaver())  # BẮT BUỘC có checkpointer
config = {"configurable": {"thread_id": "t1"}}
graph.invoke({"draft": "..."}, config)            # dừng, kết quả có "__interrupt__"
graph.invoke(Command(resume="yes"), config)       # chạy tiếp với cùng thread_id
  • interrupt() dừng graph, lưu state; resume bằng Command(resume=value) và giá trị đó thành giá trị trả về của interrupt().
  • Khi resume, node chứa interrupt chạy lại từ đầu node → code trước interrupt phải idempotent (không side-effect lặp).
  • Cách tĩnh (cũ hơn, dùng để debug): compile(interrupt_before=["tools"]) hoặc interrupt_after=[...].
  • Bốn mẫu HITL: approve/reject, edit state, review tool call, validate input người dùng.

Streaming

stream_mode Trả về
"values" Toàn bộ state sau mỗi bước
"updates" Chỉ phần node vừa cập nhật
"messages" Token LLM + metadata (node nào phát ra)
"custom" Dữ liệu tự phát qua get_stream_writer()
"debug" Thông tin chi tiết từng bước

Multi-agent

Kiến trúc Cách hoạt động
Supervisor Một agent điều phối chọn agent con nào làm tiếp; agent con báo lại supervisor
Network / Swarm Agent tự chuyển quyền (handoff) cho nhau bằng Command(goto=..., graph=Command.PARENT)
Hierarchical Supervisor của các supervisor (team lồng nhau)
Tool-calling Agent con được bọc thành tool cho agent chính gọi
  • Functional API (thay cho Graph API): @entrypoint(checkpointer=...) cho workflow, @task cho đơn vị công việc; vẫn có persistence và interrupt.
  • Durability mode khi chạy: "exit", "async", "sync" (đánh đổi tốc độ và độ bền dữ liệu checkpoint).

7. Guardrails: khái niệm

Guardrail là lớp kiểm tra đặt ở các điểm then chốt (input, output, tool call, retrieval) để chặn, sửa hoặc đánh dấu nội dung không an toàn. Không có guardrail nào đủ một mình → phòng thủ nhiều lớp (defense in depth).

Đặt guardrail ở đâu

Vị trí Kiểm tra gì Ví dụ
Input rail Trước khi vào LLM Prompt injection, jailbreak, PII, off-topic, độc hại
Retrieval rail Đoạn văn RAG lấy về Injection gián tiếp, tài liệu không được phép đọc
Execution / tool rail Trước khi chạy tool Duyệt bởi người (HITL), kiểm tra args, giới hạn quyền
Output rail Trước khi trả user Lộ PII/secret, độc hại, hallucination, sai format
Dialog rail Luồng hội thoại Giữ đúng chủ đề, kịch bản cố định

Deterministic vs model-based

Deterministic (rule) Model-based (LLM/classifier)
Cách làm Regex, keyword, schema, allow/deny list LLM-as-judge, Llama Guard, moderation API
Ưu Nhanh, rẻ, dự đoán được Hiểu ngữ nghĩa, bắt vi phạm tinh vi
Nhược Dễ bị né, bỏ sót ngữ cảnh Chậm, tốn tiền, có thể sai (false positive/negative)

Hành động khi phát hiện vi phạm

  • Block / refuse: dừng và trả lời từ chối.
  • Redact / mask / hash: che dữ liệu nhạy cảm rồi xử lý tiếp.
  • Fix / re-ask: sửa output hoặc yêu cầu LLM tạo lại.
  • Escalate: chuyển cho người duyệt.
  • Log / flag: cho qua nhưng ghi lại để monitor.

Mã Rủi ro Guardrail tiêu biểu

  • Jailbreak là một dạng prompt injection nhằm vượt qua chính sách an toàn của model.

8. Guardrails: triển khai

Trong LangChain 1.x, guardrail = middleware gắn vào create_agent; ngoài ra có hai thư viện chuyên dụng là Guardrails AI và NVIDIA NeMo Guardrails.

LangChain middleware

from langchain.agents import create_agent
from langchain.agents.middleware import (
    PIIMiddleware, HumanInTheLoopMiddleware, before_agent, AgentState)

@before_agent(can_jump_to=["end"])
def block_keywords(state: AgentState, runtime):
    text = state["messages"][0].content.lower()
    if "hack" in text:
        return {"messages": [{"role": "assistant", "content": "Không thể hỗ trợ."}],
                "jump_to": "end"}          # dừng sớm, không gọi model
    return None

agent = create_agent(
    model="openai:gpt-4o", tools=[send_email, search],
    middleware=[
        block_keywords,                                          # lớp 1: rule
        PIIMiddleware("email", strategy="redact", apply_to_input=True),
        PIIMiddleware("api_key", detector=r"sk-[a-zA-Z0-9]{32}", strategy="block"),
        HumanInTheLoopMiddleware(interrupt_on={"send_email": True, "search": False}),
    ],
    checkpointer=InMemorySaver(),   # HITL cần checkpointer + thread_id
)
# resume sau khi duyệt:
agent.invoke(Command(resume={"decisions": [{"type": "approve"}]}), config)
PIIMiddleware strategy Kết quả
redact (mặc định) Thay bằng [REDACTED_EMAIL]
mask Che một phần, ví dụ ****-****-****-1234
hash Thay bằng hash cố định (vẫn so khớp được)
block Ném exception
  • PII có sẵn: email, credit_card (kiểm Luhn), ip, mac_address, url; loại khác tự định nghĩa qua detector (regex hoặc hàm).
  • Tham số: apply_to_input (mặc định True), apply_to_output (False), apply_to_tool_results (False).
  • HITL quyết định: approve, edit (sửa args), reject (kèm lý do).
  • Guardrail đầu vào → before_agent; kiểm tra câu trả lời cuối → after_agent; kiểm tra từng bước → before_model / after_model.

Câu hỏi tự kiểm tra

1Khác nhau giữa add_edge và add_conditional_edges?

Edge thường luôn đi cố định; conditional gọi hàm router đọc state để chọn node kế tiếp.

2Khi nào dùng Send thay vì conditional edge?

Khi số nhánh song song chỉ biết lúc chạy (map-reduce), mỗi nhánh nhận state riêng.

3Command giải quyết vấn đề gì?

Cho node vừa cập nhật state vừa điều hướng trong một lần trả về; dùng cho handoff giữa agent.

4Bốn chế độ stream chính?

values, updates, messages, custom.

5Hook middleware nào để chặn request trước khi gọi model lần nào?

before_agent với can_jump_to=["end"] và trả {"jump_to": "end"}.

6Vì sao dùng MMR trong retriever?

Cân bằng độ liên quan và độ đa dạng, tránh lấy nhiều chunk trùng ý.

7chunk_overlap để làm gì?

Giữ ngữ cảnh ở ranh giới giữa hai chunk.

8Prompt injection gián tiếp là gì? Cách giảm thiểu?

Chỉ dẫn độc nằm trong dữ liệu agent đọc (web, PDF, email). Giảm bằng cách coi dữ liệu là dữ liệu, lọc retrieval, giới hạn quyền tool, HITL cho hành động nhạy cảm.

9Deterministic hay model-based guardrail cho phát hiện số thẻ tín dụng?

Deterministic (regex + Luhn): nhanh, chính xác, rẻ.

10Excessive Agency (LLM06) phòng thế nào?

Ít tool nhất có thể, quyền tối thiểu, giới hạn số lần gọi, người duyệt trước hành động không đảo ngược được.
